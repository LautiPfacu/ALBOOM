ALBOOM

Instructivo: del diseño a la app publicada

Al terminar vas a tener ALBOOM funcionando en tu computadora, el código en GitHub, los datos en Firebase y la app publicada en Vercel. Claude Code escribe el código dentro de Visual Studio Code; vos lo guiás, probás y aprobás cada paso.

Antes de empezar
  • Una computadora con Windows 10 o más nuevo, o con macOS.
  • Un plan pago de Claude (Pro o superior) para usar Claude Code.
  • Una cuenta de Google (para Firebase) y una de Spotify Premium.
  • El paquete design_handoff_alboom_v2 descargado.
  • Una o dos horas para la configuración inicial (pasos 1 a 5). Se hace una sola vez.

1

Instalá las herramientas

Una sola vez · 20 minutos

Node.js

Entrá a nodejs.org, descargá la versión LTS e instalala con las opciones por defecto. Es lo que hace andar Vite y React en tu computadora.

Git

Entrá a git-scm.com y descargalo. En Windows se llama «Git for Windows»: instalalo con las opciones por defecto. Git guarda la historia de tu código y lo sube a GitHub.

Visual Studio Code

Descargalo de code.visualstudio.com e instalalo.

Claude Code dentro de VS Code

  1. Abrí VS Code y andá a Extensiones: Ctrl + Shift + X en Windows o Cmd + Shift + X en Mac.
  2. Buscá «Claude Code», elegí la que publica Anthropic y tocá Instalar.
  3. Abrí un archivo cualquiera y tocá el ícono de la chispa arriba a la derecha. La primera vez te pide iniciar sesión con tu cuenta de Claude en el navegador.

Necesitás un plan pago de Claude (Pro o superior). La extensión trae Claude Code adentro; no hace falta instalar nada más.

Revisá que todo quedó instalado

En VS Code abrí la terminal (menú Terminal → Nueva terminal) y escribí, de a una:

node -v
npm -v
git --version

Cada línea tiene que devolver un número de versión. Si dice que no reconoce el comando, cerrá y volvé a abrir VS Code.

Presentate ante Git

En la misma terminal, con tu nombre y el mail que vas a usar en GitHub:

git config --global user.name "Tu Nombre"
git config --global user.email "tu@mail.com"
2

Creá las cuentas

10 minutos
  • GitHub: donde vive el código.
  • Vercel: donde se publica la app. Entrá con «Continue with GitHub» para que queden conectadas.
  • Firebase: cuentas de usuario y base de datos. Entrás con tu cuenta de Google.
  • Spotify for Developers: los datos de los discos. Entrás con tu cuenta de Spotify; tiene que ser Premium.
3

Prepará la carpeta

5 minutos
  1. Descargá el paquete design_handoff_alboom_v2 (está en el chat) y descomprimilo dentro de una carpeta nueva llamada ALBOOM, por ejemplo en Documentos.
  2. En VS Code: Archivo → Abrir carpeta → elegí ALBOOM. Si pregunta si confiás en los autores, respondé que sí.
  3. Abrí la terminal (Terminal → Nueva terminal). Tiene que estar parada en la carpeta ALBOOM.

Claude Code va a crear el proyecto en una carpeta alboom al lado del paquete. Vas a terminar con ALBOOM/design_handoff_alboom_v2 y ALBOOM/alboom.

4

Configurá Firebase

15 minutos
  1. En la consola de Firebase tocá «Crear un proyecto», ponele alboom y seguí. Google Analytics lo podés desactivar.
  2. En la página del proyecto tocá el ícono </> («Agregar app web»), ponele alboom-web y registrala. Te muestra un bloque firebaseConfig: dejá esa pestaña abierta, vas a copiar apiKey, authDomain, projectId y appId en el paso 6.
  3. Menú Compilación → Authentication → Comenzar → Método de acceso: activá «Correo electrónico/contraseña» y «Google».
  4. Menú Compilación → Firestore Database → Crear base de datos → ubicación southamerica-east1 (São Paulo) → modo producción.
  5. Pestaña Reglas de Firestore: cuando Claude Code tenga listo firestore.rules, copiás todo su contenido ahí y tocás Publicar. Repetilo cada vez que una fase cambie las reglas.
5

Configurá Spotify

5 minutos
  1. En el Dashboard tocá Create app.
  2. Nombre: ALBOOM. Descripción: «Diario de discos». En Redirect URIs poné http://127.0.0.1:5173 (es obligatorio completarlo aunque ALBOOM no lo use).
  3. En «Which API/SDKs are you planning to use?» marcá Web API, aceptá los términos y guardá.
  4. Entrá a Settings y copiá el Client ID. Tocá «View client secret» y copiá el Client secret.
El Client secret es como una contraseña. No se lo pases a nadie, no lo pegues en el chat de Claude y no lo subas a GitHub. Solo va en el archivo .env (paso 6) y en Vercel (paso 9).
6

Arrancá con Claude Code

La primera fase lleva varias sesiones
  1. Abrí el panel de Claude Code (ícono de la chispa).
  2. Abrí design_handoff_alboom_v2/PROMPT_CLAUDE_CODE.md, copiá el «Mensaje inicial» completo y pegalo en el panel.
  3. Claude lee los dos README y te propone un plan. Leelo: si te cierra, respondé «OK»; si no, pedile cambios.
  4. Mientras trabaja te va a pedir permiso para crear archivos y correr comandos (por ejemplo, instalar paquetes). Leé qué va a hacer antes de aceptar.
  5. Cuando cree alboom/.env, abrilo vos y completalo con los datos de Firebase (paso 4) y de Spotify (paso 5). Guardá.
VITE_FIREBASE_API_KEY=…
VITE_FIREBASE_AUTH_DOMAIN=…
VITE_FIREBASE_PROJECT_ID=…
VITE_FIREBASE_APP_ID=…
SPOTIFY_CLIENT_ID=…
SPOTIFY_CLIENT_SECRET=…

Sin espacios alrededor del = y sin comillas.

7

Probá en tu computadora

En la terminal:

cd alboom
npm run dev

Abrí http://localhost:5173 en el navegador. Cada cambio que hace Claude se ve al instante. Para frenar el servidor: Ctrl + C en la terminal.

8

Subí el código a GitHub

5 minutos
  1. En GitHub tocá New repository, ponele alboom, elegí público o privado según pida la cátedra y no marques «Add a README» (lo escribe Claude). Crealo y copiá la dirección que termina en .git.
  2. Pedile a Claude Code:
Inicializá git en alboom, hacé el primer commit y conectalo con
https://github.com/TU-USUARIO/alboom.git. Antes del commit mostrame
git status y esperá mi OK.
Antes de aceptar el commit, mirá la lista de git status: .env no tiene que aparecer. Si aparece, frená y pedile que lo saque.

La primera vez, Git te va a pedir iniciar sesión en GitHub desde el navegador.

9

Publicá en Vercel

10 minutos
  1. En Vercel: Add New → Project → importá alboom desde GitHub.
  2. Framework: Vite (lo detecta solo). No cambies los comandos.
  3. Abrí Environment Variables y cargá las 6 variables de tu .env, con los mismos nombres y valores.
  4. Tocá Deploy. Al terminar te da una dirección del tipo alboom-xxxx.vercel.app.
  5. En Firebase → Authentication → Configuración → Dominios autorizados → agregá esa dirección (sin https://). Sin esto, el login no funciona en la versión publicada.

Desde ahora, cada git push a GitHub publica una versión nueva sola, en uno o dos minutos.

10

El ciclo de todos los días

  1. Abrí VS Code en la carpeta ALBOOM y el panel de Claude Code.
  2. Arrancá la fase que sigue con el mensaje «Al empezar cada fase nueva» de PROMPT_CLAUDE_CODE.md.
  3. Probá con npm run dev cada pantalla que termine.
  4. Cuando la fase anda: pedile lint, build, commit con el tag y push.
  5. Revisá la versión publicada en Vercel.

Las fases

1V1: login, búsqueda, biblioteca y página de discov1.0
2Logo, ilustración del login y logo animadov1.1
3Primera vez: géneros, discos y temav1.2
4Los cuatro temasv1.3
5Vistas de la biblioteca, fecha de escucha y «Escuchado» en verdev1.4
6Comunidad: reseñas públicas, disco nuevo, Tendencias y Explorarv2.0
7Perfil y ajustes, seguridad y ayudav2.1

Consejos

  • Pedí una cosa por vez. Si pedís cinco juntas, es más difícil revisar.
  • Pedile que te explique lo que hizo: lo vas a tener que defender en la demo.
  • Si la conversación se hace muy larga o Claude se confunde, abrí una nueva y decile en qué fase estás. Todo lo importante está en los README.
  • Guardá los mensajes que le mandás: la consigna pide ejemplos.
  • Hacé commit seguido. Si algo se rompe, siempre podés volver al último que funcionaba.

Si algo falla

El login dice auth/unauthorized-domainFalta el dominio en Firebase → Authentication → Configuración → Dominios autorizados (paso 9).
Aparece Missing or insufficient permissionsLas reglas de Firestore no están publicadas o son viejas. Copiá de nuevo firestore.rules y publicalas (paso 4).
La búsqueda anda en tu compu pero no en VercelFaltan las variables SPOTIFY_* en Vercel. Cargalas y, en Deployments, tocá «Redeploy».
Al recargar /biblioteca en Vercel sale un 404Falta vercel.json en la raíz del proyecto. Viene en el starter.
Cambié el .env y no pasa nadaFrená npm run dev con Ctrl + C y volvé a correrlo. En Vercel, hacé Redeploy.
Algo se rompió y no sé qué cambióPedile a Claude: «Mostrame qué cambió desde el último commit y volvé a esa versión si hace falta.»

Para cualquier otro error: copiá el mensaje completo de la consola o la terminal y pegáselo a Claude con «Encontrá la causa, explicámela y arreglalo con el cambio mínimo».
